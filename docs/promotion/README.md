# docs/promotion —— 对外发表与推广文稿

这里放「写给仓库外面的人看」的稿件，工程文档（RFC、`使用文档.md`、`进度记录.md`、`会话交接.md`）
仍在 `docs/` 根目录。分开的理由只有一个：这两类文稿的生命周期不同——工程文档跟着代码改，
发表稿一旦发出去就以当时版本为准，改法只能是「另存新稿」，不能就地覆盖（见 `AGENTS.md` §5）。

| 文件 | 体裁 / 用途 | 面向 |
|---|---|---|
| [仓颉版Tauri-博客稿.md](仓颉版Tauri-博客稿.md) | 博客体：定位、三层结构、`create → dev` 流程、两平台各一个必踩的坑 | 中文技术社区（CSDN / 掘金 / 博客园） |
| [cj-tauri-IPC-通信机制-博客稿.md](cj-tauri-IPC-通信机制-博客稿.md) | 深挖稿：IPC 报文形状、异步分发线程模型、能力校验与事件回投 | 中文技术社区，偏架构读者 |
| [仓颉版Tauri-介绍与使用指南.md](仓颉版Tauri-介绍与使用指南.md) | 指南体：能力全景、命令/插件/多窗口用法、平台矩阵 | 准备上手的中文开发者 |
| [推广渠道与投稿草案.md](推广渠道与投稿草案.md) | 内部规划：逐渠道评估（能投 / 不能投 / 为什么）+ 可复用英文 slogan、150 词介绍 | 只给维护者做决策用 |
| [cj-tauri-devto-en.md](cj-tauri-devto-en.md) | 英文技术稿：dev.to / Hashnode 形态（同样的架构叙事 + 真机踩坑） | 海外开发者 |

两点约定：

- **事实口径按当前版本**。上面每一份里出现的版本号、插件数、示例数、测试数、产物体积都以
  `CHANGELOG.md` 顶部已发版段为准；英文稿是 2.1.0 口径，中文博客稿是更早一轮的口径，
  重新发布前各自核一遍。
- **图片不走仓库相对路径**。发表稿里的截图链接要用可公开访问的直链（AtomGit `raw` 路径取不到文件时
  换 GitHub `raw`，或按各平台要求另传图床），所以移动本目录不影响既有图片引用。
