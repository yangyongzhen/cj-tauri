# 分发形态实测：Windows 单文件 exe 与 Linux 目录式

产物多大、带不带第三方依赖、开窗要多久——这三个数决定「能不能直接把一个文件甩给没装开发环境的人」。
手抄一张表没人能复核，所以这些数字一律由 `scripts/dist-report.sh` 现场量、连同口径写进
`dist/dist-report.json`（证据目录，不入库）；本文只做转述与解释，并**写明哪些还没验**。

## 一、数据（2026-10-13，宿主 Linux）

Windows 单文件（随仓库分发的那一份，`examples/*/dist-single/`）：

| 产物 | 体积 | 字节 | sha256 前 12 位 | PE 导入 DLL | 非系统 DLL |
|---|---|---|---|---|---|
| `modbus-poll.exe` | 5.59 MB | 5862400 | `d0a078e688d0` | 8 | 0 |
| `movie.exe` | 9.42 MB | 9881088 | `a416b76ad67a` | 9 | 0 |
| `music.exe` | 9.50 MB | 9956864 | `7926f25bfcb5` | 9 | 0 |
| `typing-poem.exe` | 5.50 MB | 5766656 | `7c78979135eb` | 8 | 0 |
| Linux 目录式（`main` + 随包共享库） | 11.31 MB | 11862828 | — | — | — |

对比图见 `docs/images/dist-size-compare.svg`（同一份实测数据生成，图与数同源）。

Linux 侧那行是「可执行文件 4.47 MB + 随包共享库 6.84 MB」——**Linux 没有单文件形态**，
要把 `libcjtbridge.so`、仓颉运行时与 stdx 的 `.so` 一起带上（`ldd` 解析出 140 项依赖，
其中不在系统目录里的才算随包）。

## 二、「免安装」到底免掉了什么

1. **依赖只有 Windows 自带的组件**。四份产物的导入表加起来一共 9 个名字，全是系统 DLL：
   `KERNEL32` / `USER32` / `SHELL32` / `ole32` / `msvcrt` / `WS2_32` / `comdlg32` / `dbghelp`（崩溃栈回溯），
   `movie` 与 `music` 多一个 `CRYPT32`（https 走 Windows 证书库）。
   判据很直白：**表里没有任何第三方运行时 DLL**（`msvcp*` / `vcruntime*` / `libgcc*` / `libwinpthread*` 一个都没有），
   也没有 Node 相关的东西。`scripts/dist-report.sh` 会按系统 DLL 白名单分类，
   出现白名单以外的名字就单独列出来——「免安装」这句话，看的就是这一列是不是 0。

2. **子系统是 GUI**：`Subsystem 00000002 (Windows GUI)`（objdump 实测）——双击不会先弹一个控制台黑窗口。

3. **不需要 SDK**：仓颉运行时就静态链在产物里（所以导入表里没有它的 DLL），
   从没装过仓颉 SDK 的机器上直接跑得起来——这一点在此前的便携包/单文件实机验收里已经取证过
   （窗口起来、页面自检全过），本轮补的是「导入表层面只有系统 DLL」这条静态证据。

4. **边界要说清楚，不然就是吹**：
   - npm 上的 `npx cj-tauri` 是**脚手架/CLI**，那一步要 Node；`create` 出来的工程里跑 `cjpm build` 要 SDK。
     所以这是「**已构建的产物**免安装」，不是「开发链路零依赖」。
   - Windows 上仍要**系统级**的 WebView2 运行时（Win10/11 通常自带，缺了装一次 Evergreen Runtime 即可）。
   - 单文件不等于零落盘：首次运行会把内嵌的 `WebView2Loader.dll` 释放到 `%TEMP%\cj-tauri-loader\` 再按绝对路径加载。
     用户不用管路径，但别对外说成「不写磁盘」。

## 三、冷启动

**口径**：进程启动 → 桥打印 `[cj-bridge] set window: title=` 那一行；10ms 轮询，跑 3 次取中位数。
取这一行的理由：它是「窗口真的立起来了」的最早可观测点，而且两平台由同一份 core 打印，跨平台可比；
它前面是宿主创建与能力位协商，后面才是页面加载——只等「窗口出现」（或干脆不等）都验不到这一段。

**实测（Linux，`examples/serial-waveform`）**：48 / 54 / 57 ms，**中位数 54 ms**。

**Windows 侧未量**：本机是 Linux，跑不了 exe。口径已经写进脚本——在 Windows 上跑同一个脚本，
它会自动改成量 exe（宿主平台选侧）。缺的是机器，不是方法，所以这一栏在补齐之前一律留空，
不拿 Linux 的数字替 Windows 说话。

## 四、怎么自己复核

```bash
bash scripts/dist-report.sh --runs 3 --svg docs/images/dist-size-compare.svg
```

- 体积与哈希：直接对 `examples/*/dist-single/*.exe`（`sha256sum` 与本文表格对得上就是对得上）。
- 导入表：`objdump -p <exe> | grep "DLL Name"`——Linux 上也能读 PE，不必等 Windows 机器。
- 冷启动：脚本按宿主平台自动选侧，Windows 上再跑一次即可。

## 五、还没验的（别当卖点）

- **Windows 冷启动**：等 Windows 机器；口径已在脚本里。
- **单文件形态下 `libssl-3-x64.dll` / `libcrypto-3-x64.dll` 的落法**：这两个是仓颉运行时的 TLS 加载器
  **按名字**去加载的，导入表里看不见它们。目录式便携包由 `scripts/pack-win.sh` 随包分发；
  单文件包本机未能验证其释放路径，**未复现之前不写结论**。
- **Linux 侧没有单文件形态**：要带可执行文件 + 随包 `.so`；https 用的 openssl 由系统包提供
  （本机 `/usr/lib/x86_64-linux-gnu/libssl.so.3` 696512 B + `libcrypto.so.3` 5305304 B，**不随包**），
  这一点与 Windows 侧不同，两边不能混着说。
