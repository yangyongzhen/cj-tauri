# 安全模型

> 本文回答两个问题：cj-tauri 的攻击面是什么、每一层防线由谁强制执行。
> 所有断言都在 `src/tests/` 里有对应用例（README「安全模型：可被外部审视的证据」一节给了对照表），
> 设计决策的「为什么」见 `docs/设计决策记录.md`（ADR）。

## 威胁模型

**信任边界只有一条：页面是不可信的。** 前端是任意 Web 技术栈（可能内联、可能 Vite 构建、
可能是第三方内容），仓颉后端与能力清单是可信的。宿主实现（C 桥 / 平台代码）按「系统边界」对待，
不放行逻辑进宿主——判定逻辑只在共享层（`src/capability.cj` / `src/scope.cj`），平台不另判一份。

页面能做的事被收窄到四类入口，每类都有独立防线：

| 入口 | 页面能构造什么 | 防线 |
|---|---|---|
| `invoke` 命令 | 任意命令名 + 任意参数 | 命令白名单（`commands`）+ 命令必须已注册 |
| `emit` 事件 | 任意事件名 + 载荷 | 事件白名单（`events`） |
| 插件命令的路径参数 | 任意路径（含 `../` 穿越） | 路径 scope（allow/deny + 规范化） |
| 插件命令的 URL 参数 | 任意 URL（SSRF） | 主机白名单（`scopes.http` / `scopes.ws`），没写 = 全拒 |

## 分层防线

### 1. 默认最小权限（命令与事件）

- 能力清单（`capabilities/*.json`）是**唯一放行来源**：`commands` / `events` / `permissions` 三张名单，
  不在名单里的一律拒绝。
- 空清单 = 全拒（`testRegistryEmptyDeniesEverything`）——没有「缺省全开」的形态。
- 未授权 / 未注册在 IPC 校验层**同步拒绝**（回 reject、stderr 留 `command not allowed` /
  `command not registered`），只有通过校验的命令才进 worker 线程。

### 2. 命名权限集（v1.1）

- 插件用 `Plugin.permissions()` 声明「短集名 → 成员」，清单用 `"permissions": ["fs:readonly"]` 引用；
  展开后与明文名字**同权**，单层展开、不递归。
- **集声明 ≠ 放行**：插件声明了集而清单没引用，不生效（`testRegisteredPermissionSetNotReferencedStaysDenied`）；
  清单引用了没人提供的集名，只提示不报错、不静默放行（`testPermissionSetWithoutProviderIsInert`）。

### 3. 路径 scope（RFC-003）

- **命令放行 ≠ 参数放行**：`scopes` 把「这个插件允许碰哪些路径」单独定死，先 deny 后 allow，
  allow 必须显式命中——空 allow = 该插件路径全拒。
- 匹配前规范化：存在走 `canonicalize`（顺带解软链接），不存在走词法折叠 `.` / `..`；
  模式 `*` 不跨目录分隔符、`**` 跨、`?` 单字符。
- 插件显式声明 `scopeAware()` 才吃这层限制；没写 scope 的旧清单行为不变（启动打一行 stderr 提示）。
- 越界拒绝打 `scope denied (<插件名>): <原文> -> <规范化路径>`，前端拿到的是业务错误。

### 4. 运行期加白的收口

- `TauriApp.allowScopePattern` 叠加层与清单同权、同一把锁（命令分发是异步的）；
  **注册中心只收具体值**——模式里出现 `*` / `?` 或制表/换行当场拒（`testRuntimeAllowExtendsManifestScope`）。
  一个通配透传进来就等于全放行，这条不变量由注册中心强制，应用绕不过。
- 加白**掀不掉 deny**（先 deny 后 allow 不破）；清单没写 `scopes` 的插件不叠加（那时本就全量放行）。
- 确认交互归应用：框架不做确认 UI（它不理解应用的语义），推荐仓颉侧弹原生确认框——
  页面点不了原生对话框，被注入的脚本也就无法自行加白。

### 5. 出网口收口（SSRF）

- http / ws 插件对页面可控 URL 做**主机白名单**：`scopes.http` / `scopes.ws` 没写 = 全拒；
  端口不参与匹配、userinfo 不许伪造主机、非 http(s)/ws(s) 协议拒、IPv6 字面量单独识别
  （host 提取在共享层 `src/urlutil.cj`，http 与 ws 用同一份，禁两份实现）。
- 禁自动重定向、Host / Content-Length 不许页面自带、8 MiB 截断上限。

### 6. 进程与插件边界

- 子进程一律 **argv 直传**（`launch` / `executeWithOutput` 收参数数组），不拼 shell 命令串。
- 插件间不得互相引用（链接粒度 = 插件包 = 静态库，用哪个链哪个）；子包可见父包 `public` 符号、
  反向禁止——`check-static.sh` 有 grep 级断言守住包边界。
- 命令异步分发（worker 线程），worker 里只经 `jsSink` 回投；拒绝与异常都**回投前端 + stderr 留痕**，
  没有「无声失败」的通道。

## 与 Tauri 2 安全模型的对比

| 维度 | Tauri 2 | cj-tauri | 说明 |
|---|---|---|---|
| 权限来源 | capabilities + 插件 permission 文件（ACL） | `capabilities/*.json` 一处 | 思路同源：默认拒绝、逐命令声明 |
| 权限集 | 有（`fs:allow-*` 系列，多层默认集） | 有，但**单层展开、不递归** | 刻意做浅：展开规则一眼看完 |
| 路径 scope | `fs:scope`（allow/deny glob） | 同形，先 deny 后 allow + 显式命中 | 语义对齐；空 allow 全拒这点更严 |
| 运行期加白 | runtime authority（`RuntimeAuthority`） | `allowScopePattern` 叠加层 | 都收口在注册中心；这里**拒一切通配** |
| 事件 ACL | 不做 | `events` 白名单 | cj-tauri 事件同样过校验层 |
| 出网口 | 插件各自实现（http 插件有 scope） | http/ws 主机白名单共享一份判定 | 白名单缺失 = 全拒 |
| 外部审计 | 1.0 时做过第三方审计 | 未审计；以「设计可审视 + 断言可复跑」代偿 | README 证据表 + `scripts/test.sh` 可复跑 |

## 已知边界（如实说）

- 宿主能力（对话框 / shell 打开链接等）走平台 API，放行与否仍由命令白名单决定，
  但平台 API 本身的行为（如系统文件框的可访问范围）超出框架可控范围。
- 没做外部安全审计——「可被外部审视」的代偿是：设计集中在两份共享层文件里、
  每条防线有可复跑的断言、拒绝路径全部留 stderr 凭证。
- CSP：页面由应用自己提供，框架不注入 CSP 头；能力白名单是后端防线，
  前端 XSS 防护（输入转义等）仍是应用的责任。
