# cj-tauri 工具类示例计划

> 这份文档管**示例选题**：做哪些「常用工具」类示例、按什么顺序做、每款的展示点与验收判据。
> 与 `docs/需求追踪.md` 的分工：那份管**框架能力项**（CORE / SEC / PLG / PLT / ENG），只在被示例
> 驱动时才登记新能力位；这份只管「下一款工具做什么」。选题有变改本文件，做完把状态列改成 done 并补示例路径。
> 建立于 2026-10-13（用户圈定四款入选，其余留备选）。

## 1. 判据（四条，按重要性）

1. **名字即共识**——一听就知道是什么的工具才有传播力（Postman、任务管理器、DB Browser 这类）。
   小众硬核工具（CAN 总线、抓包）圈内叫好，但出圈难，不作为知名度抓手。
2. **界面本该是 Web 的强项**——表格、图表、Markdown、消息流都算；纯前端就能做的（JSON 格式化）、
   或必须吃原生控件的（录屏、截图取色），展示「系统 WebView + 仓颉后端」的性价比就弱。
3. **能顺带推进框架空白**——当前**托盘**暂缓（用户裁定）、**全局快捷键 / Window State / Single Instance /
   Logging / HTTP 代理**还在 RFC-003 第 5 期「按需排期」。选题正好需要它俩的，一款示例换一个能力位。
4. **能无人值守自检**——按 `AGENTS.md` §1 的门禁，交付凭证是实机 stderr 双侧对账；凡只能靠人眼看图的
   工具（截图、录屏、排版美化），验证成本要按倍数算（AGENTS §4「自检全绿 ≠ 界面没问题」也在这条上）。

## 2. 总表

| 工具（对标） | 状态 | 知名度 | 展示的框架能力 | 需补的能力位 / 依赖 | 工作量 | 可验证性 |
| --- | --- | --- | --- | --- | --- | --- |
| Markdown 笔记 / 编辑器（Typora） | **入选 ①** | 高 | 前端零 Node + `fs`（含路径 scope）+ `store` + 单文件打包 | 无新插件、无新能力位 | 小 | 强（落盘字节 + 渲染后 DOM 结构都能断言） |
| HTTP API 客户端（Postman / HTTPie） | **入选 ②** | 极高 | 仓颉侧 HTTP/HTTPS（TLS 走系统证书库）+ `fs` 集合存取 + 事件通道 | 无新能力位 | 中 | 强（本地 mock server 双侧对账） |
| SQLite 数据库浏览器（DB Browser for SQLite） | **入选 ③** | 高 | **FFI 到第三方原生库**（`sqlite3`）+ 大表格虚拟滚动 | 新增插件 `sqlite` + `sqlite3` 动态库（三平台分发 + LICENSE 登记） | 中 | 强（脚本建库 → 断言查询结果） |
| 剪贴板历史管理器（Ditto / Win 剪贴板历史） | **入选 ④** | 高（大众向） | `clipboard` 插件 + `store` 持久化 + 热键唤出面板 | **全局快捷键**（planned）+ **托盘**（暂缓）两个能力位 | 中 | 中（写入剪贴板 → 断言历史捕获；热键用 xdotool 模拟） |
| 系统资源监视器（任务管理器 / htop） | 备选 | 高 | 「平台差异只在两处」的架构卖点（Linux `/proc` vs Windows PDH）+ 实时曲线走事件通道 | 很可能要新增 Windows 侧 C 桥实现（性能计数器） | 大 | 中（数值可断言，曲线靠图） |
| 双栏文件管理器（Commander 风） | 备选 | 中高 | `fs` + 路径 scope + 文件拖入（已 supported） | 无 | 中 | 中（大目录虚拟滚动是主要工作量） |
| 托盘常驻小工具（番茄钟 / 网速悬浮窗） | 备选（被 ④ 覆盖） | 中高 | 托盘能力位本身 | **托盘**（暂缓） | 中 | 中 |
| 消息队列调试台（Kafka / RabbitMQ） | 备选 | 中高（后端向） | 第三条协议线，复用 mqtt / redis 同一套插件形状 | 无 | 中 | 强 |

## 3. 入选四款（按实现顺序）

顺序判据是用户定的「先紧着**容易且有价值**的」：**前置依赖越少越先做**，被框架能力位卡住的排后面。

### ① Markdown 笔记 / 编辑器（`examples/markdown-notes/`）

> **状态：已交付（2026-10-13）** —— 见 `examples/markdown-notes/`（该目录 README 有操作与自检说明），
> Linux 实机 E2E `scripts/e2e/test-linux-markdown-notes.sh` **25/25 断言全过**；Windows 侧未验证。
> 与下面当初设想的差异（如实记档）：**表格与任务清单未做**（有意收窄渲染器表面积）、
> 自动保存改成 `Ctrl+S` + 「未保存」标记、新建不弹窗问名字（页内自动取名 `新笔记.md`）、
> 形态是三栏（左文件树 / 中编辑 / 右预览）而不是两栏；`fs` 插件为此补了 `list` / `remove` 两条命令。

- **形态**：左编辑 / 右预览（可分栏可切换），工作区 = 一个本地目录（文件树 + 新建 / 重命名 / 删除），
  自动保存与「未保存」标记，偏好（主题、字体、预览开关）走 `store` 持久化。
- **复用与新增**：复用 `fs`（读写作区，**清单里给它写 `scopes`**）与 `store`；**不新增插件、不碰 C 桥**。
  Markdown 解析**自写子集**（标题 / 强调 / 列表 / 任务清单 / 代码块 / 表格 / 链接 / 引用），
  不引第三方库——省掉 LICENSE 登记与三平台分发，且解析结果可被断言（见下）。
- **展示点**：前端零 Node（无需 bundler，页面直接读盘或内嵌）、单文件打包可行、
  **路径 scope 的真实用法**（清单把 `fs` 限制在工作区目录：越界被拒并有 `[cj-tauri] scope denied` 日志）、
  能力白名单（未声明命令一律 `command not allowed`）。
- **验收判据（无人值守）**：探针建临时工作区 → 写文件 → `fs` 读回断言**字节一致**（落盘证据）→
  断言渲染后的 **DOM 结构**（标题层级 / 代码块 / 表格行列 / 任务项勾选数，由页面把计数回投 stderr）→
  重命名 / 删除 / 重新打开 → 断言 scope 越界被拒（负向）。**渲染正确性不靠人眼的部分全部量化**；
  剩下的排版观感仍按 AGENTS §4 抓图人眼验一次。
- **不做**：WYSIWYG 富文本、图片粘贴上传、双链 / 知识图谱、导出 PDF/HTML 之外的格式、多标签页。
- **风险**：Markdown 子集解析器是自写的，得配页面侧单测（纯 JS 函数），否则每加一个语法都得实机验。

### ② HTTP API 客户端（`examples/http-client/`）

> **状态：已交付（2026-10-13）** —— 见 `examples/http-client/`（该目录 README 有操作、契约与自检说明），
> Linux 实机 E2E `scripts/e2e/test-linux-http-client.sh` **55/55 断言全过**（页内自检 34/0）；Windows 侧未验证。
> 与下面当初设想的差异（如实记档）：请求体**只做 raw 文本**（form-urlencoded / multipart 未做）、
> 查询串**直接写在地址里**（没有独立的参数表格 UI）、白名单是**示例自己注册的命令**而非框架能力位
> （理由见 `docs/设计决策记录.md` D-017）、E2E 对端是本仓自写的 `mock-http.py` 而**不是** `http.server`
> （自写才有「两侧都有日志」这个对账前提）、集合存的是**未展开的原文**（换个变量集就能换目标）、
> 历史保留最近 30 条。

- **形态**：请求构建（方法 / URL / 查询参数 / 头 / 体：raw-JSON、form-urlencoded、multipart）+
  响应查看（状态码、耗时、响应头、体：原文与 JSON 树切换）+ 集合与历史（`fs` 落 JSON，**带 scope**）+
  环境变量集（`{{base_url}}` 之类）。
- **复用与新增**：`stdx.net.http`（`movie` 示例已踩过 TLS / `readToEnd` / `getFirst` 三个坑，照抄即可）；
  `fs` 存集合；不新增插件、不碰 C 桥。
- **展示点**：仓颉侧直接发 HTTPS（**TLS 走系统证书库**，不是关校验）、前端零 fetch、
  大响应体经 IPC 回投的边界（分块 / 截断如实上报）。
- **验收判据（无人值守）**：E2E 起 python3 `http.server`（标准库）做 mock 对端 ——
  断言回投的**状态码 / 响应头 / 体**逐字一致，集合与历史**落盘字节**可断言，对端侧日志记到实际收到的
  方法、路径、头与体（两侧对账）。负向：连不上 / 超时 / 4xx-5xx 都有明确错误行。
- **不做**：WebSocket（另立选题）、HTTP/2 细节开关、证书管理 UI、抓包代理、OAuth 授权流程。
- **风险**：E2E 要能离线跑，所以**不拿公网 https 端点当断言锚点**（可留一个显式可选的手工检查项）。

### ③ SQLite 数据库浏览器（`examples/sqlite-browser/`）

- **形态**：打开 `.db` 文件 / 表与视图列表 / 结构查看（建表 DDL、索引）/ 数据分页浏览（虚拟滚动）/
  SQL 编辑器 + 结果表格 / 结果导出 CSV。
- **复用与新增**：新增官方插件 `sqlite`（`src/plugins/plugin_sqlite.cj`），**FFI 声明随插件放同目录**
  （AGENTS §2「谁调用谁包内」）；命令按「只读集 + 写集」两个命名权限集声明（照 `fs` / `redis` 的做法）。
- **展示点**：**仓颉 FFI 到第三方原生库**——这是目前唯一能把「仓颉不只有标准库」讲清楚的样板；
  以及大结果集的 IPC 分页契约。
- **前置（必须先解决）**：`sqlite3` 动态库的**三平台分发**（Linux `.so` / Windows `.dll`）与
  `AGENTS.md` §5 的第三方登记（来源 + 许可证）；`scripts/pack-win*.sh` 的 DLL 清单要补一行
  （不在 PE 导入表里、按名字加载的库最容易漏，见 AGENTS §4 的 WebView2Loader / OpenSSL 两例）。
- **验收判据（无人值守）**：E2E 用 python3 的 `sqlite3` 模块建库并灌数据（对端先自证），
  再断言插件回投的表列表 / 结构 / 分页内容 / DML 行数；写操作**落盘后由 python3 侧复查**（两侧对账）。
- **不做**：多库连接池、迁移工具、ER 图、加密库（SQLCipher）、导入 Excel。
- **风险**：库分发与 FFI 名称的平台差异是这一款的真正工作量，SQL 与表格反而是容易的部分。

### ④ 剪贴板历史管理器（`examples/clipboard-history/`）

- **形态**：常驻托盘 + 全局热键唤出面板 + 历史列表（文本 / 图片缩略）搜索 + 点击回写剪贴板 +
  置顶 / 删除 / 清空 + 持久化（`store`，重启不丢）。
- **复用与新增**：`clipboard` 插件已有（读写 + `HostCapabilities` 在 Windows 是 validation-only）；
  **前置 = 两个框架能力位**：① **全局快捷键**（RFC-003 第 5 期，planned）② **托盘**（暂缓，用户裁定）。
- **展示点**：常驻型桌面应用的完整形态（托盘 + 热键 + 面板），以及**新能力位怎么按现有契约加进来**
  （`WebViewHost` 接口 → 各平台实现 → C 桥同名导出 → 主机级回调走句柄路由）。
- **验收判据（无人值守）**：外部工具（`xclip` / `xdotool`）写剪贴板 → 断言历史捕获与去重；
  热键用 `xdotool key` 模拟（`examples/menu` 已有 xdotool 实机取证先例）；点击回写后**外部回读**剪贴板内容。
- **不做**：云同步、跨设备、快捷键自定义 UI、富文本 / 文件块的完整还原。
- **风险 / 前置**：这是四款里唯一要**先改框架**的（两个能力位），且 Linux 托盘依赖
  `libayatana-appindicator3`——所以排最后，也正好作为「能力位扩容」的下一个驱动。

## 4. 备选与暂缓

| 工具 | 为什么现在不做 |
| --- | --- |
| 系统资源监视器 | 展示力最强但**很可能要新增 Windows 侧 C 桥实现**（性能计数器 / PDH）；等有 Windows 实机窗口期再做 |
| 双栏文件管理器 | 与 `plugin-fs` / `fs` 插件的展示面高度重叠，边际价值低；且大目录虚拟滚动本身就是一笔工作量 |
| 托盘常驻小工具 | 被 ④ 覆盖：它同样要托盘能力位，而 ④ 多了「大众知名度 + 剪贴板真实场景」 |
| 消息队列调试台 | 第三条协议线，与 `mqtt` / `redis` 展示面重复度高（同族第三款，边际递减）；有真实 Kakfa/RabbitMQ 环境时再做 |
| 抓包 / 代理、录屏、截图取色 | 判据 2 与判据 4 都不满足（原生控件 + 只能人眼验），成本高且难自证 |

## 5. 每款做完的固定动作（与 `AGENTS.md` §7 一致）

1. 框架 / 示例 `cjpm build` 零警告（`AGENTS.md` §3）；
2. `bash scripts/test.sh` + `bash scripts/check-static.sh` 全绿；
3. 实机跑一轮并落 E2E 入口 `scripts/e2e/test-linux-<示例>.sh`（`run-all.sh` 靠 `ls test-*.sh` 自动收录，
   只需复用公共层与平台守卫）+ 证据 `dist/e2e-evidence/`；
4. 文档同步：`CHANGELOG.md` 的 `[Unreleased]`、`README.md` 示例表、`docs/需求追踪.md`（若动了能力位）、
   `docs/进度记录.md`（本轮段）、示例目录的 `README.md`；
5. 按双仓约定入库双推（`git push origin main`）。

## 6. 维护规则

- 新增选题先过 §1 四条判据，再进 §2 总表（状态 = 入选 / 备选 / 暂缓 / done）。
- 某款做完把状态改 `done`，补示例目录路径与 E2E 入口名。
- 若某款被框架能力位卡住（如 ④），**先把能力位登记进 `docs/需求追踪.md` 的 PLG 表**，再回来做示例——
  别让示例绕过框架契约直接调平台 API（`AGENTS.md` §2 的架构契约就是这么被破的）。
