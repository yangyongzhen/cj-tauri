# 仓颉版 Tauri（cj-tauri）技术方案

> 日期：2026-08-21
> 目标目录：`tauri_cj/`
> 环境：Linux x86_64，仓颉 SDK 1.0.5 (cjnative) + cjpm 1.0.5，WebKitGTK 2.52.3

---

## 一、背景与目标

仿照 Tauri（Rust 后端 + 系统 WebView 前端）架构，用华为仓颉语言实现轻量混合开发框架。
可行性已由《仓颉版Tauri可行性报告.md》论证：语言能力闭环（编译/互操作/条件编译）具备、
鸿蒙 ArkWeb 有官方 `arkweb_cangjie_wrapper`、社区已有 `webview-sdk` 雏形。

本机为 **Linux x86_64 桌面环境**（有 X display），故本次落地：

- **P0 目标（本次交付）**：Linux 桌面端跑通 Tauri 三件套——WebView 宿主、IPC 双向桥、
  能力安全模型，附示例应用与 CLI 脚手架；
- **架构预留**：WebView 宿主抽象层 + 条件编译位，为鸿蒙 ArkWeb 后端预留接口
  （鸿蒙侧需 DevEco + 真机，本机不具备，架构上留位）。

## 二、总体架构（对标 Tauri 三件套）

```
┌─────────────────────────────────────────────┐
│                前端 (HTML/CSS/JS)             │
│   window.__CJ_TAURI__.invoke / listen / emit │   ← 注入的桥接 JS（对标 @tauri-apps/api）
└───────────────┬─────────────────────────────┘
                │ JSON over postMessage (WebKitUserContentManager script message)
┌───────────────▼─────────────────────────────┐
│                IPC 消息桥 (ipc.cj)            │   ← 命令注册/分发/事件推送（对标 tauri IPC）
└───────────────┬─────────────────────────────┘
┌───────────────▼─────────────────────────────┐
│        能力安全模型 (capability.cj)           │   ← 命令/事件白名单校验，默认最小权限（对标 capability）
└───────────────┬─────────────────────────────┘
┌───────────────▼─────────────────────────────┐
│          内置命令 API (api/system.cj)         │   ← version/ping/echo
└───────────────┬─────────────────────────────┘
┌───────────────▼─────────────────────────────┐
│        WebView 宿主抽象 (host/host.cj)        │   ← 接口层（对标 WRY+TAO）
│   ┌───────────────────────────────────────┐ │
│   │ Linux: webkit2gtk-4.1 实现 (C FFI)     │ │   ← 本次实现
│   │ 鸿蒙:  ArkWeb (arkweb_cangjie_wrapper) │ │   ← 预留（条件编译 os/backend）
│   └───────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

对应关系：

| Tauri 组件 | 仓颉版 | 说明 |
|---|---|---|
| WRY + TAO | `host/` | 窗口创建 + WebView 渲染；Linux = webkit2gtk-4.1 直绑（同 WRY 做法） |
| IPC（invoke/event） | `ipc/` | JS→CJ 用 UserContentManager 消息通道；CJ→JS 用 run_javascript |
| capability 能力模型 | `capability/` | JSON 权限清单 + 校验层 |
| tauri.conf.json | `app.json` / `cjpm.toml` | 应用配置 + 依赖 |
| @tauri-apps/api | 注入的 `__CJ_TAURI__` JS | 前端 API 面 |
| tauri-cli | `cli/cj-tauri` | create / dev / build |

## 三、IPC 协议设计

采用 **JSON over postMessage**，与 WRY 同构（WebKitUserContentManager 注册 `cjtauri` 消息处理器，
页面用 `window.webkit.messageHandlers.cjtauri.postMessage(...)` 发送）。

### 3.1 JS → 仓颉：invoke（请求）

```json
{ "type": "invoke", "id": 1, "cmd": "greet", "args": { "name": "world" } }
```

### 3.2 仓颉 → JS：resolve / reject（响应）

```json
{ "type": "resolve", "id": 1, "ok": true,  "data": "hello world" }
{ "type": "resolve", "id": 1, "ok": false, "error": "command not allowed: greet" }
```

### 3.3 仓颉 → JS：event（事件推送）

```json
{ "type": "event", "event": "tick", "payload": { "n": 1 } }
```

响应/事件经 `run_javascript` 投递到页面，前端 `__CJ_TAURI__` 用 `Promise` + 订阅表分发。

### 3.4 序列化

仓颉 1.0.5 标准库无 `std.json`。框架自带轻量 JSON 解析/生成器（`json.cj`），
支持 object/array/string/number/bool/null 全子集，作为框架基础件。

## 四、能力安全模型（capability）

对标 Tauri `capabilities/*.json`：

```json
{
  "identifier": "default",
  "windows": ["main"],
  "commands": ["greet", "system:version", "system:ping"],
  "events":   ["tick"]
}
```

- 应用启动时从 `capabilities/` 目录加载清单；
- IPC 分发前校验：**未声明命令一律拒绝**（默认最小权限），拒绝返回 `error: command not allowed`;
- 事件推送侧校验：未声明事件不投递到页面；
- 校验层独立于宿主实现，鸿蒙侧复用同一套。

## 五、WebView 宿主层（host/）

### 5.1 抽象接口 `WebViewHost`

```cangjie
interface WebViewHost {
    func create(options: WindowOptions): Unit     // 创建窗口+WebView
    func run(): Unit                               // 进入事件循环
    func loadHtml(html: String): Unit
    func runJs(js: String): Unit                   // 原生→JS
    func destroy(): Unit
}
```

### 5.2 Linux 实现（本次）

C FFI 直接绑定 webkit2gtk-4.1：

| 能力 | C API |
|---|---|
| 窗口/主循环 | `gtk_init` / `gtk_window_new` / `gtk_main` / `g_signal_connect` |
| WebView | `webkit_web_view_new` / `webkit_web_view_load_html` / `webkit_web_view_run_javascript` |
| JS→CJ 通道 | `webkit_user_content_manager_register_script_message_handler("cjtauri")` |
| 桥接 JS 注入 | `webkit_user_script_new` + `add_script` |

C 回调经 `CFunc` 转入仓颉（注意：仓颉 1.0.5 对 GObject 回调需持有全局引用防 GC）。

### 5.3 鸿蒙预留

`host/harmony.cj` 占位 + 条件编译：`@When(backend == "ohos")`（仓颉条件编译特性）。
实现时以 `arkweb_cangjie_wrapper` 的 `WebviewController` 为宿主、`javaScriptProxy`/`runJavaScript` 为桥
（对应 Eclipse 移植 OpenHarmony 的方案）。本机无 DevEco，交付占位接口与设计说明。

## 六、框架模块划分（tauri_cj/src/）

```
tauri_cj/
├── cj-env.sh                      # 环境配置（CANGJIE_HOME/PATH/LD_LIBRARY_PATH）
├── cjpm.toml                      # 框架包定义（库）
├── src/
│   ├── json.cj                    # 轻量 JSON 解析/生成（框架基础件）
│   ├── app.cj                     # TauriApp：装配（配置+命令注册+capability+宿主）
│   ├── ipc/
│   │   ├── message.cj             # InvokeRequest/ResolveMessage/EventMessage 模型
│   │   ├── ipc.cj                 # IpcHub：命令注册、分发、校验、事件推送
│   │   └── command.cj             # 命令处理器接口 + 上下文
│   ├── capability/

│   ├── api/

│   ├── host/
│   │   ├── host.cj                # WebViewHost 接口 + 平台选择
│   │   ├── webkit_ffi.cj          # webkit2gtk-4.1 C FFI 声明
│   │   └── webkit_host.cj         # Linux WebKitHost 实现
│   └── assets/
│       └── bridge.js              # 注入前端的 __CJ_TAURI__ 桥接脚本
├── examples/hello/                # 示例应用
│   ├── cjpm.toml                  # 依赖 cj-tauri
│   ├── src/main.cj                # 应用入口：注册 greet 命令
│   ├── capabilities/default.json  # 权限清单
│   └── ui/index.html              # 前端（含 main.js 内联）

└── tests/                         # 单元测试（json/capability/ipc 纯逻辑）
```

## 八、验收标准

1. `examples/hello` 真实运行（X display）：窗口出现、前端渲染、`invoke("greet")` 返回结果、事件推送刷新 UI；
2. 未声明命令（如 `system:rm`）被 capability 拒绝并返回错误，前端可感知；
3. `cj-tauri create` 生成的新项目可独立编译运行；
4. 框架源码无第三方依赖，纯仓颉 + 系统 WebView。

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| 仓颉 1.0.5 FFI 对 GObject 回调支持边界 | 回调闭包持全局引用；先做最小 C 程序验证再全量实现 |
| 无 std.json | 自实现轻量 JSON（框架基础件，可控） |
| 服务器无 GPU/真实桌面 | DISPLAY=localhost:10.0 可用；WebKit 有软件渲染回退 |
| 鸿蒙侧无法本机验证 | 架构留位（接口+条件编译），文档说明 DevEco 集成路径 |
