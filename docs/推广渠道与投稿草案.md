# cj-tauri 国外推广：渠道评估与可投稿素材

> 面向「让国外开发者知道并用上 cj-tauri」。先给结论与边界，再给逐渠道素材。
> 事实核对时间：2026-10-26。仓内可直接做的改动已全部落地（见 §1），外发动作需用户授权（见 §6）。

## 0. 一句话结论

**不能靠「向国外一堆仓库投稿」来推广**——mass PR 属于垃圾推广，会被仓库举报、GitHub 账号可能被限流或封禁，
而且 cj-tauri 与绝大多数列表的主题不符（最典型的 `awesome-tauri` 只收「用 Tauri 做的项目」，
cj-tauri 是受 Tauri 启发的另一套框架，投进去会被判离题删除）。

**真正的杠杆是三件事**：① 让仓库「一眼可读」（英文描述 / 英文 README 入口 / 英文站点）；
② 在**允许自荐**的社区与目录站各发一次（数量少、质量高）；
③ 拿得出**可直接下载试用的产物**（Windows exe / npm 一行命令）。

## 1. 已在仓内完成的曝光改进（2026-10-26）

| 改动 | 改前 | 改后 | 为什么重要 |
|---|---|---|---|
| GitHub 仓库描述 | 全中文 | 英文（Tauri-inspired hybrid desktop framework for Cangjie…） | 搜索与推荐流按描述文本匹配，中文描述对英文检索几乎不可见 |
| Discussions | 关闭 | 开启 | 外国用户提问入口；Issue 区保持干净，便于「good first issue」运营 |
| Homepage 链接 | AtomGit（国内域名） | GitHub Pages | 海外访问 AtomGit 不稳定，首页落到 `.github.io` 更可靠 |
| README 首屏 | 无英文入口 | 「简体中文 · English」切换 | `README_EN.md` 此前**没有任何入口**，等于不存在 |
| npm keywords | 已较好（cangjie / tauri / webview…） | 未改 | 已覆盖主要检索词 |

**仍缺、且是最大短板**：官网 `website/index.html` 只有中文。外国开发者点进主页看到中文页面，
转化率基本为零。补一个英文落地页 `<website>/en/`（或 `index_en.html`）是投入产出最高的一步。

## 2. 逐渠道评估

### 2.1 ❌ 不建议：`awesome-tauri` 等离题列表

- `awesome-tauri` 的收录标准是「用 Tauri 构建的应用 / 插件 / 模板」。cj-tauri **不是 Tauri**，
  是一套独立实现（仓颉后端 + 系统 WebView），投进去大概率被关 PR 甚至被标记 spam。
- 同理，`awesome-rust` / `awesome-electron` 等均离题。
- **只在「确实对口」的列表投**：若存在 `awesome-cangjie` 这类仓颉生态列表，可以投；投前先读 CONTRIBUTING。

### 2.2 ✅ 推荐：目录站与替代品站点（提交即排队，规则宽松）

| 站点 | 入口 | 要求 | 备注 |
|---|---|---|---|
| OpenAlternative | openalternative.co 的 submit 表单 | 开源 + 英文站点/README + logo | 与 Tauri 同场对比，天然流量 |
| LibHunt | libhunt.com 的 add project | GitHub 仓库 URL 即可 | 自动按 topic 归类 |
| AlternativeTo | alternativeto.net 提交 | 需说明「是 Tauri 的替代品」 | 上传英文描述与截图 |

这三处**只需提交一次表单**，不必写长文；填的内容直接取英文 README 首段。

### 2.3 ✅ 推荐：Show HN（一次机会，必须自己写）

- HN 官方规则明确：**禁止 AI 生成的投稿文本**，且新账号发 Show HN 容易被埋。
  所以这一条**只能由你自己写**，我不能代笔（写了也是违规文本，且一眼能看出）。
- 可用的结构（自己用英文展开，不要照抄）：
  1. 一句话说清「这是什么」：*a Tauri-like desktop framework for Cangjie*；
  2. 为什么做：Cangjie 编译成静态二进制、用系统 WebView、产物几 MB；
  3. 现在能做什麼：三端跑通 + 二十多个示例 + 一行 `npx`；
  4. 诚实的短板：生态新、文档以中文为主、鸿蒙侧部分能力位未落地。
- **前提**：英文落地页 + 可下载产物就绪后再发，否则 HN 评论区第一问「how do I try it」就没法接。

### 2.4 ⚠️ 谨慎：Reddit

- `r/coolgithubprojects`、`r/opensource`、`r/programming` 允许自荐但各有频率限制；
  `r/programming` 对自荐极其严格，容易直接被删。
- 建议只发 `r/coolgithubprojects`（明确是展示新项目的地方），**一次一条，之后不要重复刷**。

### 2.5 ✅ 推荐：英文技术文章

- 已有中文博客稿 `docs/仓颉版Tauri-博客稿.md`，翻成英文后发 dev.to / Hashnode（两站都吃 Markdown、SEO 好）。
- 英文选题比「介绍框架」更容易起量：*Building a desktop app in Cangjie with the system WebView*、
  *Why we didn't bundle Chromium: a few-MB desktop app with Cangjie*。

### 2.6 ✅ 推荐：Product Hunt

- 需要英文落地页 + 截图 + 一行 slogan，一次发布机会；建议在英文站上线后再做。

### 2.7 其他

- **Cangjie 官方社区 / 华为开发者论坛**：中文为主，但对「仓颉生态第一个桌面框架」这类项目曝光最有效。
- GitHub 侧运营：给 1–2 个示例仓打 `good first issue`、在 Discussions 里发一次「Roadmap / What's next」，
  都能提高活跃度信号（GitHub 推荐流偏好有讨论的仓）。

## 3. 可复用的英文物料（直接取用）

**一句话（slogan）**

> Tauri-style desktop apps, written in Cangjie — static-compiled backend, system WebView frontend, few-MB binaries.

**一段介绍（150 词内，用于目录站表单）**

> cj-tauri is a hybrid desktop framework for the Cangjie language. Your UI is plain HTML/CSS/JS rendered
> by the system WebView (WebView2 on Windows, WebKitGTK on Linux, ArkWeb on HarmonyOS); your backend is
> Cangjie compiled into a static binary. There is no bundled Chromium, so a full app ships in a few
> megabytes. It provides a bidirectional IPC bridge, a capability whitelist covering commands, events,
> filesystem paths and outbound hosts, a plugin system with 14 official plugins, and a CLI that scaffolds
> projects and takes over Vite dev servers. Verified end-to-end on Windows, Linux and HarmonyOS PC with
> unattended self-checks in every example. MIT licensed.

**要点清单（用于任何介绍场景）**

- 仓颉 / Cangjie backend, system WebView frontend, no bundled browser engine
- binaries 4.7–10.3 MB; `npx cj-tauri create my-app` to start
- IPC bridge + capability whitelist (commands / events / path scope / host allowlist)
- 14 official plugins, 20+ runnable examples, MIT

## 4. 顺序建议（投入产出比从高到低）

1. **英文落地页**（唯一的结构性短板，其余渠道都依赖它）；
2. **目录站三连**（OpenAlternative / LibHunt / AlternativeTo，提交即完成）；
3. **英文技术文章一篇**发 dev.to；
4. **Show HN**（自己写，等产物与英文站就绪）；
5. Reddit 一条、Product Hunt 一次（可选）。

## 5. 不要做的事

- ❌ 向 `awesome-tauri` 及任何「非仓颉生态」的 awesome 列表投稿——离题，等于自曝 spam。
- ❌ 同一内容在多仓重复开 PR、在多个 subreddit 连刷——会触发账号风控。
- ❌ 让我代写 Show HN 正文——HN 明文禁止 AI 生成内容。
- ❌ 在别人的 issue / discussion 里贴推广链接——典型的「不请自来」，对声誉是负资产。
