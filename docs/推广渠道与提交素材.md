### 3.1 一句话（≤50 字，HelloGitHub 的「项目标题」用）

### 3.2 短简介（200 字上下，HelloGitHub 的「项目描述」32–256 字符区间）

> cj-tauri 是仓颉语言里的类 Tauri 混合桌面框架：后端用仓颉静态编译，前端是系统 WebView 里的 HTML/CSS/JS，两者靠 IPC 双向桥和能力白名单连起来。它不捆绑 Chromium，产物几 MB 级；自带串口、子进程、剪贴板、通知、原生菜单、文件拖放等宿主能力，以及 CLI 脚手架，`npx cj-tauri create myapp` 就能起步。Windows 与 Linux 已实机跑通，仓库里有 17 个可直接运行的示例，其中一个能当串口实时波形示波器用。

### 3.3 亮点三条（HelloGitHub「亮点」栏，也是任何介绍的第一段素材）

> 1. **不捆绑 Chromium**：前端用系统 WebView（Windows 的 WebView2 / Linux 的 WebKitGTK），后端是仓颉静态编译的原生可执行文件，产物几 MB 级；
> 2. **能力安全模型**：命令与事件必须写进 `capabilities/*.json` 才放行，插件只声明「我提供什么」、不自动授权，另有命名权限集与路径 scope；
> 3. **全链路可验证**：仓内自带 E2E 基建（脚本 + 证据 JSON）与 17 个示例，示例能自己给自己下结论（比如串口示波器跑完输出 `verdict=ok` 与 404.2 样本/s）。

### 3.4 长简介（150–300 字，PR 描述 / 目录站「项目介绍」栏）

> cj-tauri 是一个用华为仓颉语言实现的类 Tauri 混合桌面开发框架。它的三件套是：系统 WebView 宿主、
> IPC 双向桥（`invoke` / `resolve` / 事件回投）、能力白名单安全模型。后端静态编译，前端就是普通的
> HTML/CSS/JS，不需要 Node（Vue / React 模板另带 `ui/` 工程，`cj-tauri dev` 会接管 Vite dev server）。
> 目前有 8 个官方插件（文件、对话框、子进程、串口、键值存储、剪贴板、通知、菜单），17 个可直接运行的
> 示例，以及 `create / dev / build / run / info / doctor` 一条 CLI。平台状态按实测说：Windows（WebView2）
> 与 Linux（WebKitGTK）已实机跑通，鸿蒙 ArkWeb 为架构预留位、能力位如实报 0。代码 MIT，仓库在
> AtomGit（`https://atomgit.com/qq8864/cj-tauri`），npm 包是 `cj-tauri`。

- 📌 **配图直链（实测，别踩空）**：AtomGit 的 `/raw/<路径>`、`/-/raw/<路径>`、`/blob/<路径>`、
  `raw.atomgit.com/<...>` 四种形态**都返回前端 HTML**（`content-type: text/html`，连 `README.md`
  都一样，取不到文件字节）；`api.atomgit.com/api/v5/repos/<owner>/<repo>/raw/<路径>` 无凭据拿到的也
  不是原文件。**结论：AtomGit 目前不能当图床。**
  可用的是 GitHub 镜像的 raw，例如
  `https://raw.githubusercontent.com/yangyongzhen/cj-tauri/main/docs/images/example-serial-waveform.png`
  ——实测 `200 image/png`、92686 字节，与仓内文件大小一致（架构图同址换成 `architecture.png`，379460 字节）。
  发帖配图就用这个；要换成别的图床也行，但**别用 AtomGit 的 raw**。
