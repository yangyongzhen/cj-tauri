## 二、M2 做了什么（代码已落盘）

- `cli/src/main.cj`：`create <工程名> [--template <t>]`，支持 `-t` / `--template`，**缺省仍是 `app`**（老用法不变）。
- `cli/src/scaffold.cj`：模板目录名不再硬编码，按参数取 `cli/templates/<t>`。
- `cli/templates/app-vue/`：Vue 3 + Vite + `vite-plugin-singlefile`，产物打成单个 `ui/dist/index.html`
  （框架是把页面读成字符串交给 WebView 的，页面没有基准路径，发布态必须单文件）。
- `cli/src/project.cj`：
  - `dev`：有 `ui/package.json` 才走 Node 路径 —— 缺 `node_modules` 先 `npm install`；后台起 `npm run dev`
    （输出重定向到 `ui/dev-server.log`）；等日志出现 Vite 的 `Local:` 行（最多 180 秒）；注入
    `CJ_TAURI_DEV_URL` 再启动应用；应用退出后 `taskkill /F /T` 收掉 dev server 整棵进程树。
  - `build`：有 `ui/package.json` 时先 `npm run build` 并检查 `ui/dist/index.html` 产出，再编译仓颉应用
    （**该分支本轮未实机验证**）。

## 四、下一步（按优先级）

1. **HMR —— 已澄清并证实（不再是缺口）**。改 `ui/src/App.vue` 会依次触发
   `[file change]` → `[self-accepts]` → `[vue:update(template)]` → `[vite] (client) hmr update /src/App.vue`，
   也就是说 **`vite-plugin-singlefile` 没有破坏 dev HMR**。此前三次「没观测到」是判据错了：
   Vite 的模块图要**客户端请求过页面之后**才建立，当时没有客户端连上来，日志里只有 `[no modules matched]`。
   复现方式（不必编译仓颉、几十秒就能跑完）：把 `cli/templates/app-vue/` 拷成一个临时工程 →
   `cd ui && npm install` → `DEBUG=vite:hmr node node_modules/vite/bin/vite.js` →
   `curl` 一遍 `/`、`/src/main.js`、`/src/App.vue`（等价于页面连上）→ 覆盖 `ui/src/App.vue` →
   日志里应出现 `[vite] (client) hmr update`。
2. **窗口内 HMR 取证 —— 已完成**（走「页面自报 DOM」的路线，不需要截图）：把工程 `ui/src/App.vue` 换成
   每秒 `invoke('greet', { name: 'TICK--' + <h1 的真实文案> })` 的探针，再覆盖成文案更长的版本。实测：

   ```text
   覆盖前  js -> native (76 bytes)        ← 探针在报 v1 的文案（短）
   覆盖后  js -> native (173 bytes) / (174 bytes)   ← 报的是 v2 的新文案（长）
   Navigate = 1（全程没变）  Reload = 0   ← 整页没有重载
   dev server 日志：[vite] (client) hmr update /src/App.vue
   ```

   即「HMR 更新已下发 → 窗口里的页面跑起了新代码 → 而且没有整页刷新」，三点同时成立。
   收尾也正常：`应用退出（exit=1）` → `dev server 已收掉（pid=…）`，`node.exe` / `main.exe` 无残留。
3. **两模板的端到端复测**：React 侧走一次 `cj-tauri dev`；Vue 侧补一次 `cj-tauri build` 分支（含 `npm run build` 检查）。

## 五、本机环境（照抄能省很多时间）

- 仓颉 SDK：`D:\Program Files (x86)\Cangjie`；`CANGJIE_HOME` 用 Windows 形式，
  `PATH` 里要加 SDK 的 `bin` / `tools/bin` / `runtime/lib/windows_x86_64_cjnative` / `tools/lib`
  以及 `native/`（`libcjtbridge.dll` 所在）。
- 跑 CLI / 测试一律带 SDK `PATH`，否则表现为**退出码 127 且无输出**（动态链接找不到运行时 DLL）。
  Git Bash 里 PATH 要用 POSIX 形式（`/d/...`），不能用 `D:/...`。
- **npm 冷启动极慢**：`npm run dev` 把 Vite 拉起来最慢约 85–150 秒（Vite 自身只要 0.3 秒）。
  想快可直接 `node ui/node_modules/vite/bin/vite.js`。
- **bash 工具单次调用结束时，这次调用里起的后台进程会一起被收掉** —— 不要指望「上一步起 Vite、下一步改文件」，
  一次调用里把「起服务 → 等就绪 → 改文件 → 取证 → 收尾」做完整。
- MSYS：`pgrep` 看不到 Windows 原生进程（判残留要用 `tasklist`）；`hdc file recv` 的远端绝对路径要加
  `MSYS_NO_PATHCONV=1`；`start` 的内联引号会被吃掉。
- 真机（3QC0124B20000048）用 `aa start` 要求屏幕已解锁，开发者模式下无法自动解锁，需人工解锁后再测。
