## 二、M2 做了什么（代码已落盘）

- `cli/src/main.cj`：`create <工程名> [--template <t>]`，支持 `-t` / `--template`，**缺省仍是 `app`**（老用法不变）。
- `cli/src/scaffold.cj`：模板目录名不再硬编码，按参数取 `cli/templates/<t>`。
- `cli/templates/app-vue/`：Vue 3 + Vite + `vite-plugin-singlefile`，产物打成单个 `ui/dist/index.html`
  （框架是把页面读成字符串交给 WebView 的，页面没有基准路径，发布态必须单文件）。
- `cli/src/project.cj`：
  - `dev`：有 `ui/package.json` 才走 Node 路径 —— 缺 `node_modules` 先 `npm install`；后台起 `npm run dev`
    （输出重定向到 `ui/dev-server.log`）；等日志出现 Vite 的 `Local:` 行（最多 180 秒）；注入
    `CJ_TAURI_DEV_URL` 再启动应用；应用退出后收掉 dev server 整棵进程树（Windows `taskkill /F /T`；
    其他平台按「先子后父」递归 kill —— `setsid` 方案会让 Ctrl-C 漏跑，教训见 `AGENTS.md` §4）。
  - `build`：有 `ui/package.json` 时先 `npm run build` 并检查 `ui/dist/index.html` 产出，再编译仓颉应用
    （该分支已在 Linux 上实机验证，见 §3.1）。

## 五、本机环境（照抄能省很多时间）

### 5.1 Windows（WebView2，M1/M2/M3 的验收机）

- 仓颉 SDK：`D:\Program Files (x86)\Cangjie`；`CANGJIE_HOME` 用 Windows 形式，
  `PATH` 里要加 SDK 的 `bin` / `tools/bin` / `runtime/lib/windows_x86_64_cjnative` / `tools/lib`
  以及 `native/`（`libcjtbridge.dll` 所在）。
- 跑 CLI / 测试一律带 SDK `PATH`，否则表现为**退出码 127 且无输出**（动态链接找不到运行时 DLL）。
  Git Bash 里 PATH 要用 POSIX 形式（`/d/...`），不能用 `D:/...`。
- **npm 冷启动极慢**：`npm run dev` 把 Vite 拉起来最慢约 85–150 秒（Vite 自身只要 0.3 秒）。
  想快可直接 `node ui/node_modules/vite/bin/vite.js`。
- **bash 工具单次调用结束时，这次调用里起的后台进程会一起被收掉** —— 不要指望「上一步起 Vite、下一步改文件」，
  一次调用里把「起服务 → 等就绪 → 改文件 → 取证 → 收尾」做完整。
- MSYS：`pgrep` 看不到 Windows 原生进程（判残留要用 `tasklist`）；`hdc file recv` 的远端绝对路径要加
  `MSYS_NO_PATHCONV=1`；`start` 的内联引号会被吃掉。
- 真机（3QC0124B20000048）用 `aa start` 要求屏幕已解锁，开发者模式下无法自动解锁，需人工解锁后再测。

### 5.2 Linux（WebKitGTK，2026-10-02 实测机）

- 仓颉 SDK：`/opt/cangjie/cangjie`；`CANGJIE_HOME=/opt/cangjie/cangjie`，`PATH` 加 `bin` / `tools/bin` /
  `tools/lib` / `runtime/lib/linux_x86_64_cjnative`，并把 `runtime/lib/linux_x86_64_cjnative` 与
  `third_party/llvm/lib` 设进 **`LD_LIBRARY_PATH`**（Linux 动态库不查 PATH，只设 PATH → 退出码 127 且无输出）。
- stdx：`/root/.cangjie/stdx/cangjie-stdx-linux-x64-1.0.5.1/dynamic/stdx`，用 `CANGJIE_STDX` 指过去。
- 图形栈：GTK + WebKitGTK；本机 `DISPLAY=localhost:12.0`（X 转发），窗口能创建、GTK 图标可设。
- 桥的诊断输出一律落 `/tmp/*.log`；临时验证工程放 `/tmp`（如本次的 `probe_vue` / `probe_react`，
  含 npm 依赖，别留在仓内）或仓内 `.tmp_dev_vue` / `.tmp_dev_react` / `.tmp_m1_verify`（本就不入库），取证完记得删。
- 清残留**别用** `pkill -f ".tmp_dev_vue"`：发起命令的 shell 自身命令行里也含这个路径，会把自己一起杀掉；
  用更精确的模式（如 `pkill -f "tmp_dev_vue/ui/node_modules"`）或把清理脚本放到 `/tmp` 再执行。
- 想模拟「终端 Ctrl-C」不能用后台 `&` 起 CLI：bash 会把 SIGINT 设成 SIG_IGN 并被子进程继承，
  现象是「怎么打都不死」，会把有问题的实现误判成没问题；用
  `timeout -s INT <秒> bash cli/cj-tauri.sh dev` 更接近真实前台语义。
- npm 包本地试装的临时目录（可随时删）：安装前缀 `/tmp/cj-npm-test`、`create` 产物 `/tmp/cj-npm-create-test`、
  CLI 本体缓存 `~/.cache/cj-tauri/<版本>/`（删掉即触发下次重新源码构建）。
